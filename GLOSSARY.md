# Shared vocabulary

[Home](README.md)

**Status:** Proposed common vocabulary. Preserve existing code identifiers unless an approved migration changes them.

| Term | Meaning in this handbook |
| --- | --- |
| Universal rule | A cross-project quality principle, applied where relevant. |
| Conditional standard | A reusable group of requirements activated by a feature, audience, or project family. |
| Project brief | The selected standards, current task context, local requirements, and exceptions for one project. |
| Source outcome | The original curriculum/lesson-level statement, retained with its provenance. |
| Canonical assessment outcome | A deduplicated assessable construct to which one or more source outcomes may map. |
| Item | A task or question with a specified response and scoring contract. |
| Evidence | An observation about learner performance, with enough context to interpret it. It is not automatically mastery. |
| Mastery | An interpretation derived under a stated learner-model rule. |
| Math/content module | A content topic or question bank, not a complete game scenario. |
| Cartridge | A MathQuest game/scenario package using the shared engine. |
| Exchange contract | The agreed fields, meanings, versions, and validation rules for exported/imported data. |
| Schema version | The version of a data format; not automatically the application's release version. |
| Project/design revision | The specific project configuration for which a generation request is valid. |
| Release version | The identity of a delivered application or document package. |
| Handbook baseline | The particular handbook revision selected for a project. |
| Snapshot | A dated export for reading or handoff, not an independently editable master. |

Shared vocabulary does not establish that all products use one storage model, one codebase, or one implemented integration.
