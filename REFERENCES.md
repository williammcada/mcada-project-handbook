## Product-content provenance

The handbook's seed content was assembled from the available conversation context and retrieved summaries of earlier project discussions. No current source packages, complete historical transcripts, or implementation dossiers were inspected for this task. The source labels under rules are descriptive provenance, not line-level transcript citations.

The distinction matters: a remembered requirement is a useful seed for a rule, but it is not a verified test result, a current application version, an implemented integration, or proof of formal global approval.

For a production build, supply the actual current source package and relevant approved specification. When promoting a shared rule to Approved, record the explicit acceptance in the decision log.
